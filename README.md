# aj-tf-module-vpn

Terraform module for AWS Client VPN — engineer access to private resources (EKS API endpoints, Aurora, Valkey) without exposing them publicly. Part of L2 in the platform stack, provisioned after `aj-tf-module-directory`.

---

## What this module does

- **Client VPN endpoint** — UDP 443, split tunnel enabled, 8-hour sessions
- **mTLS + optional AD auth** — engineers need a valid client cert; when `directory_id` is set they also need valid AD credentials (both required)
- **TLS certificates** — server cert + client CA generated by the `tls` provider, imported into ACM; no external CA dependency
- **Routes + authorization rules** — management VPC always reachable; additional workload VPC CIDRs via `additional_routes`
- **CloudWatch logs** — every connection logged (who connected, when, from where)
- **Split tunnel** — only RFC1918 traffic routes through VPN; internet bypasses it entirely

---

## How engineers connect

```
Engineer laptop (AWS VPN Client or Tunnelblick)
  → CVPN endpoint UDP 443
    → presents client cert signed by client CA
    → (if directory_id set) enters AD username + password
    → connected: virtual IP from 172.16.0.0/22
      → can reach: EKS API endpoints, Aurora, Valkey, AD

No public exposure of any private resource.
```

VPN client choice: **AWS VPN Client** (free, AWS-native, macOS/Windows/Linux) is the default recommendation. Tunnelblick (macOS, OpenVPN-compatible) also works.

## Apply order

```
Stage C1: aj-tf-module-vpc         → management VPC
Stage N1: aj-tf-module-directory   → AWS Managed AD (gives directory_id + dns_ip_addresses)
Stage N2: aj-tf-module-vpn         ← this module
            → takes directory_id + dns_ip_addresses from directory module
```

## How aj-infra-release uses this module

```bash
# provision-network.yml — after management VPC + directory are applied
terraform apply -var-file=envs/dev.tfvars \
  -var="directory_id=$(tf_output -state=directory.tfstate directory_id)" \
  -var='dns_servers=["10.200.1.5","10.200.1.6"]'
```

## Engineer onboarding (one-time per engineer)

After the VPN is provisioned:

```bash
# 1. Get the client CA key from Terraform outputs (sensitive — stored in state)
terraform output -raw client_ca_private_key_pem > ca.key
terraform output -raw client_ca_cert_pem > ca.crt

# 2. Generate engineer keypair + cert signed by the CA
openssl genrsa -out engineer.key 2048
openssl req -new -key engineer.key -out engineer.csr -subj "/CN=engineer@platform"
openssl x509 -req -in engineer.csr -CA ca.crt -CAkey ca.key -CAcreateserial \
  -out engineer.crt -days 3650

# 3. Get the .ovpn template
terraform output -raw client_config_template > engineer.ovpn

# 4. Add cert + key to the .ovpn file
cat >> engineer.ovpn << EOF
<cert>
$(cat engineer.crt)
</cert>
<key>
$(cat engineer.key)
</key>
EOF

# 5. Import engineer.ovpn into AWS VPN Client or Tunnelblick
# 6. Clean up: rm ca.key engineer.key engineer.csr
```

## Usage

```hcl
module "vpn" {
  source = "github.com/ajay-infra/aj-tf-module-vpn?ref=v1.0.0"

  vpc_id            = module.vpc.vpc_id
  target_subnet_ids = module.vpc.private_subnet_ids
  target_vpc_cidr   = "10.200.0.0/16"

  client_cidr = "172.16.0.0/22"
  split_tunnel = true

  # From aj-tf-module-directory
  dns_servers  = module.directory.dns_ip_addresses
  directory_id = module.directory.directory_id

  additional_routes = {
    dev-vpc     = "10.100.0.0/16"
    dev-data    = "10.102.0.0/16"
    staging-vpc = "10.110.0.0/16"
  }

  environment = "dev"
}
```

## Inputs

| Name | Required | Default | Description |
|---|---|---|---|
| `vpc_id` | yes | — | Management VPC ID |
| `target_subnet_ids` | yes | — | Management VPC private subnets for VPN associations |
| `target_vpc_cidr` | yes | — | Management VPC CIDR — always routed + authorized |
| `client_cidr` | no | `172.16.0.0/22` | VPN client IP range (must not overlap any VPC) |
| `additional_routes` | no | `{}` | Map of `name → CIDR` for workload VPCs |
| `split_tunnel` | no | `true` | Route only RFC1918 traffic through VPN |
| `dns_servers` | no | `[]` | AD DNS IPs pushed to VPN clients |
| `directory_id` | no | `""` | AD directory ID — enables AD auth on top of cert auth |
| `cert_validity_hours` | no | `87600` | Cert validity (10 years default) |
| `log_retention_days` | no | `90` | CloudWatch connection log retention |
| `environment` | no | `dev` | Environment label |
| `aws_region` | no | `us-east-1` | AWS region |

| `client_ca_certificate_arn` | ACM ARN of client CA cert |

## Security notes

**Client CA private key in Terraform state:** The CA key is stored in state (sensitive). Anyone with state file access can issue client certs. Mitigations:
- Use S3 state with SSE-KMS + bucket policy restricting access to infra-lead role only
- For regulated environments: replace the `tls` provider certs with AWS Private CA (`aws_acmpca_certificate_authority`) — eliminates key from state entirely

**Authorization rules:** Currently `authorize_all_groups = true` — any authenticated VPN user can reach all routed CIDRs. Lock down to AD groups once groups are established:
```hcl
access_group_id    = "infra-engineers-ad-group-id"
authorize_all_groups = false
```
